# MCP-сервер живёт в том же процессе, а Agent ходит в него in-memory транспортом

Задание требует MCP, и его можно было выполнить формально — выставить MCP-сервер
наружу для внешних клиентов, а внутренний Agent пустить прямо в функции домена.
Вместо этого MCP-сервер (FastMCP) поднимается внутри процесса приложения, и Agent
общается с ним настоящим MCP-протоколом через **in-memory transport**
(`create_connected_server_and_client_session` внутри проектного
`InMemoryMCPClient`) — без сети и без подъёма собственного HTTP-эндпоинта.
Тулы не содержат логики: каждый вызывает один и тот же application service, что и
остальное приложение.

## Considered Options

- **MCP только для внешних клиентов, внутри — прямые вызовы.** Честнее по инженерии
  и быстрее, но делает MCP декоративным: удали его — ничего не сломается.
- **Самовызов по `streamable-http`.** Так было в первой редакции этого ADR. Даёт
  ровно то же самое, что in-memory transport, плюс сетевой хоп, плюс необходимость
  выставить мутирующий MCP-эндпоинт наружу без авторизации.

## Consequences

Набор тулов — единственный контракт домена, и он один и тот же для Agent'а и для
внешнего MCP-клиента. HTTP-эндпоинт `/mcp` включается флагом и только для
демонстрации через MCP Inspector — публично мутирующий MCP без авторизации не
выставляется.

Первая редакция этого ADR обосновывала выбор тем, что синхронные тулы блокируют
event loop, а затем ссылалась на параметр `run_in_thread` standalone FastMCP.
Это не доказательство для используемого здесь `mcp.server.fastmcp.FastMCP` из
официального MCP SDK: это другая реализация с другим публичным API. Текущий выбор
не опирается на гарантию про thread pool. Тулы остаются тонкими синхронными
делегатами коротких SQLite-операций; если их latency станет значимой, execution
model SDK нужно измерить и проверить отдельно.

Модель также не является tool-calling MCP-клиентом: она возвращает JSON intent,
а `AgentService` читает Plan и применяет `apply_turn` через in-memory MCP. Это
сохраняет MCP в реальном write path, но не доказывает автономное использование
tools моделью.
